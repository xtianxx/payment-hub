## Summary

首期采用 Go 单体，使用 Gin 接收 HTTP 请求，通过 pgx 和显式 SQL 访问 PostgreSQL。Mock 位于应用内部，但保存独立的模拟交易记录。完整本地演示由一个 Go 应用容器、一个 PostgreSQL 容器，以及通过 HTTP 调用的轻量演示客户端组成。

首期业务范围仍以已批准规格为准：单接入方、单 Mock、普通订单一次性付款，无真实资金。相同支付意图复用订单，冲突请求不改写原记录；未知结果通过后续查询核实，不自动重新付款。

## Technical Context

**Language/Version**: Go；具体工具链版本尚未纳入本轮评审，不填入推测版本。

**Primary Dependencies**: Gin、pgx；goose 作为独立数据库迁移工具。首期不引入 sqlc、ORM 或依赖注入框架。

**Storage**: PostgreSQL；平台订单与 Mock 交易独立保存，数据库数据独立持久化。

**Testing**: 必须包含真实 PostgreSQL、受控故障与并发验证，以及保留数据库的实际应用重启验证；具体组织与命令待验证设计阶段确定。

**Target Platform**: 本地 Docker Compose 演示环境；不依赖云服务器，镜像及运行环境的具体版本尚未确定。

**Project Type**: HTTP 后端应用，附轻量演示客户端；不是完整商城或多服务系统。

**Performance Goals**: 本轮不设未经验证的吞吐、延迟或生产级 SLA 承诺；后续明确可验证的时间与资源限制。

**Constraints**: 仅 CNY，金额以整数分表达，范围为 1～1,000,000 分；已确认结果不得因查询故障降级；不得因超时、重启或重复请求再次付款。

**Scale/Scope**: 单接入方、单 Mock、一次性付款；退款、回调、通知、多渠道及真实资金接入不在首期范围。

## Project Structure

### Documentation (this feature)

本轮仅新增 `plan.md` 与 `research.md`；已批准的 `spec.md` 和需求质量检查清单保持不变。数据模型、合同及验证指南尚未创建，任务清单也未生成。

### Source Code (repository root)

本轮只确认模块职责，不批准具体 Go 包目录、公开类型或方法名称。下面是同一个应用内部的分工，不是五个独立服务。

| 模块 | 负责的能力 | 不承担的职责 |
|------|------------|--------------|
| HTTP 入口 | 验证身份、解析请求、入口保护、调用支付业务并转换答复 | 不直接操作支付订单表、调用 Mock 或决定付款结果 |
| 支付业务 | 提交与查询规则、重复与冲突判断、结果校验及流程编排 | 不依赖 Gin、pgx 的专用对象，不自行创建数据库连接池 |
| 平台订单存储 | 使用 pgx 和显式 SQL 兑现约定的原子操作、查询与条件保存 | 不调用 Mock，不自行发明业务规则 |
| Mock | 模拟付款、保存独立交易、查询原交易及受控故障 | 不修改平台支付订单，不靠读取平台结果假装查询渠道 |
| 启动组装 | 检查配置与依赖，手工连接模块，管理就绪、退出和资源释放 | 不隐式执行迁移，不扫描未知订单重新付款 |

### 运行组成

- **Go 应用容器**：承载上述内部模块。配置、连接池及模块对象按应用生命周期管理；每次请求的数据与事务各自独立。
- **PostgreSQL 容器**：保存平台与 Mock 各自的记录；可以共用实例和连接池，但不能共用付款事务。更新应用不得删除数据库数据。
- **轻量演示客户端**：在本地通过真实 HTTP 入口提交、查询及重放请求，不额外建设商城服务或页面。
- **数据库迁移**：goose 是明确执行的独立步骤，不是第三个必须常驻的业务进程，也不由应用启动时偷偷改表。
- **访问范围**：首期为本地受控演示。数据库不作为公网服务开放；以后若公开部署，再补充 HTTPS 入口及相应访问限制，不将公网部署算成本轮已完成能力。

### 核心编排约束

1. 先以短的本地原子操作登记支付意图；只有本次新建且登记已确认提交，当前流程才取得发起资格。读取到未知订单不等于重新获得资格。
2. 本地登记完成后，在该事务之外调用 Mock。Mock 保存自身交易，不与平台结果保存合成一个事务。
3. 取得匹配的确认结果后，有条件地可靠保存；已确认结果不得被迟到、冲突或故障信息直接覆盖。
4. 查询已有确认结果不依赖再次向 Mock 查询成功。未知订单通过查询核实原交易；Mock 无匹配记录也不能触发重新付款。
5. 各操作有明确期限；已取得可靠结果的必要保存工作有有限收尾安排，并纳入应用退出管理，不采用无人管理的后台付款任务。

### 本轮接受的限制

- 同进程 Mock 能验证故障窗口的业务处理，但不代表真实渠道网络、独立进程故障域或真实资金事务已经验证。
- 不增加后台扫描、自动补付或重启后自动续跑全部未完成付款的承诺。
- 本地演示不提供生产高可用、磁盘损坏零丢失或公网持续可访问保证。
- 简化架构不降低金额、幂等、结果保护和真实数据库验证要求。表结构、接口细节及可执行验证步骤留待后续阶段评审。
